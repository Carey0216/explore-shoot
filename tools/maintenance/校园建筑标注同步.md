# 校园建筑标注同步

标注没完成时继续在网页管理端保存即可。发布程序不把本机旧数据覆盖到数据库。

完成后，由顶级管理员打开“校园收集图 → 导出标注供版本同步”。导出包含建筑名称、片区、关联地点 ID、轮廓、内院、各楼宇修订号、基础底图版本、导出时间和完整 SHA-256；不包含用户、打卡、照片、聊天或操作者私人信息。普通管理员没有导出权限。

先在项目根目录预览下载文件：

```powershell
node tools/maintenance/atlas-sync.cjs 'C:/实际下载目录/jingyu-atlas-日期-校验值.json'
```

核对楼宇数量、已关联数、修改列表、时间和底图版本后，使用预览显示的完整校验值：

```powershell
node tools/maintenance/atlas-sync.cjs 'C:/实际下载目录/jingyu-atlas-日期-校验值.json' --apply --expect=完整SHA256
```

预览不写文件。写入时校验整份导出和基础轮廓，拒绝旧时间快照覆盖较新源码快照；校验通过后以暂存文件原子替换 `backend/src/main/resources/passport-atlas-snapshot.json`。将该资源与对应中文维护日志一起审查并提交，再构建后端。网页和小程序读取同一后端，无需分别复制楼宇数据。

新环境启动时仅补齐数据库中尚不存在的楼宇 ID；已有楼宇的名称、关联、轮廓与修订号不受源码快照影响，即使数据库修订号低于源码也不会自动替换。新增环境还需要同一套地点目录，快照不创建或发布地点；未存在或未公开的关联地点不会在用户接口泄露。

导出时间会改变整份文件的 SHA-256；标注内容另有稳定的 `contentChecksum`，只有楼名、关联、轮廓、修订或底图变动才会变化。发布前再导出一次，并比较已审阅文件和刚下载的文件：

```powershell
node tools/maintenance/atlas-sync.cjs 'C:/下载目录/已审阅.json' --compare 'C:/下载目录/最新导出.json'
```

内容版本不一致会直接报错。如果这期间继续标注，应重新核对最新导出，不能通过改校验值绕过检查。回退程序同样保留当前数据库，单栋恢复使用“编辑历史与恢复”，禁止整库覆盖。
