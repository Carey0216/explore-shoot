# v3.1：看得懂，也能动手改

这次更新围绕两件事：找地方更连贯，未提交的内容不容易丢。产品版本称 v3.1，源码版本和标签为 `3.1.0` / `v3.1.0`。

## 先用你熟悉的动作理解代码

点位列表、地图标记和下方介绍，本来是三个界面。现在它们共用一个“选中的点位编号” `state.mapSelected`。你点列表或地图时，都调用 `setupMap()` 中的 `select()`：更新列表的选中状态、突出地图标记、换成这个点位的介绍。切换点位只更新这些内容，不必重新创建地图。

草稿分成“还在浏览器里的内容”和“已经交给项目服务保存的记录”。浏览器里的 IndexedDB 可以容纳照片，刷新后仍可读取；服务器的 `data/` 存储已提交记录和媒体。**这两种存储不在同一个地方**：备份服务器的 `data/`，不会备份每台手机浏览器中的草稿。

照片选择后先压缩成 JPEG，去掉原照片的定位等元数据，再保存浏览器草稿，然后上传。任务照片只有关联到手记成功，才清除草稿。点位照片则要等整个点位发布成功才清除；“照片已上传”不等于“点位已发布”。

## 从哪里改

| 你想改的东西 | 文件与入口 | 作用 |
|---|---|---|
| 手机卡片的间距、图片大小、颜色 | `dist/user/v3.1.css` | 外观和手机/桌面差异；650px 以下采用手机布局 |
| 地图下方展示哪些内容 | `dist/user/map-explorer.js` 的 `mapPointHTML()` | 拼出点位介绍、认证提示、导航和收藏按钮 |
| 点列表后的动作、展开收起 | `dist/user/app.js` 的 `setupMap()` | 控制选中状态和按钮行为 |
| 标记突出、位置恢复 | `dist/shared/map.js` 的 `select()` / `pick()` | Leaflet 和高德地图的选中状态；点位草稿位置标记 |
| 草稿保存多久、存哪些字段 | `dist/shared/drafts.js` 的 `DRAFT_TTL` / `bindDraftForm()` | 保存、恢复、丢弃、过期、按账号及记录隔离 |
| 上传进度与照片重试 | `dist/shared/ui.js` 的 `photoPicker()` | 内建拍摄、选相册、草稿预览、真实上传进度和错误提示 |
| 发布点位如何防重复 | `server.cjs` 的 `POST /api/points` | 同一账号、同一提交编号重试时返回已有点位 |

`dist/` 虽然名字像编译输出，在这个项目中就是实际网页源码；这里不需要额外构建。CSS 负责“长什么样”，JavaScript 负责“点了以后做什么”，服务器负责“谁能做，以及提交的数据怎么保存”。

## 小练习：自己改一句文案

打开 `dist/user/map-explorer.js`，搜索“下一站，想去哪里？”，换成你喜欢的邀请语。保存，刷新用户端，打开校园地图。在没有选中点位时就能看到修改。先只改引号内的文字，保留周围的 HTML 标签和 `${...}` 插值。

第二个练习是把 CSS 中 `.map-selected-summary img` 的宽度从 `78px` 改为 `84px`，看桌面卡片的变化。手机部分有单独覆盖，因此还应检查手机尺寸。这就是“样式优先级”和“响应式布局”。

## 你可以独立做的验收

1. 打开校园地图，选两个列表项，确认标记、标题和列表高亮都跟着变化，而且没有详情弹窗。点地图标记，再检查列表选中状态。
2. 手机展开介绍，再收起；点击“到这里去”，确认导航目的地相同。关闭点位不能发起前往。
3. 发布页写名字和介绍，等待“已保存到本机”，刷新。照片、文字和地图位置分别恢复；只有本机的照片需要点击后确认上传。
4. 在独立测试环境模拟一次失败：照片留在本机，有错误说明和重试按钮。刷新、重新打开原任务的拍摄入口，恢复同一张照片。
5. 在手记里写感受，误关弹窗后再打开，检查恢复。点击保存成功，再打开，应看到账号中的内容，且没有未提交草稿。
6. 丢弃草稿后刷新，检查它不会复活。换另一个账号，不能从界面看到前一个账号的草稿。

## 本机草稿的边界

- 需要同一账号、同一浏览器、同一网址（协议、域名和端口）。临时 HTTPS 域名换了，旧网址的草稿不会自动迁移；`127.0.0.1` 和 `explore.localhost` 也各自独立。
- 每份草稿从最后一次保存起保留 7 天。无痕窗口、浏览器清理数据、卸载浏览器或系统回收存储，都可能使草稿丢失；等待“已保存到本机”后再离开。
- 按账号隔离是应用界面的隔离，不是加密保险箱。退出账号不会自动删除草稿，以便重新登录后继续。公共或借用设备使用后请在对应表单/拍摄入口丢弃草稿。
- 没有网络时，不保证刷新能重新加载整个网站；本机草稿仍在，联网后回到原网址、原表单或原任务可恢复。没有实现整站离线运行或跨设备草稿同步。
- 有些照片已上传到项目服务，但还没有关联到点位。丢弃浏览器草稿不会回滚服务器上的媒体；本版未新增后台清理孤立媒体功能。
- 同一条草稿在多标签页同时编辑，以最后完成保存的内容为准；本版未实现编辑冲突合并。

## 这次实际验证了什么

自动测试覆盖账号/记录隔离、刷新恢复、照片及文字/位置、7 天过期、配额/存储失败、丢弃与连续保存的顺序，以及成功提交后迟到事件不能恢复旧草稿。API 回归验证同一提交编号不重复发布点位，旧请求不带提交编号仍能使用。

浏览器在独立的 4188 / 4190 测试环境验证照片失败后刷新恢复、手动重试、点位文字/坐标恢复、点位发布后的草稿清理、任务照片恢复及成功关联、手记文字和评分恢复，以及 390 / 320 像素手机和 1100 像素桌面地图联动。正式数据没有用来创建测试记录。实际 iOS/Android 的相册、摄像头、系统存储回收和软键盘，仍应使用手机再验收。
