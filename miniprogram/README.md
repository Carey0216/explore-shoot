## 本机运行

1. 安装 JDK 21+、Node 20+ 和微信开发者工具，微信扫码登录并启用「设置 → 安全设置 → 服务端口」。
2. 项目根目录运行 `npm ci`、`npm run mini:check`。
3. 手机调试运行 `npm run mini:start -- -CliPath 'D:/微信web开发者工具/cli.bat'`，默认Phone模式，从仓库外部署配置读取公开HTTPS地址，先检查后端再打开工具。新克隆没有部署配置时显式传 `-ApiBase https://你的后端域名`。
4. 电脑本机模拟器使用 `npm run mini:start -- -Target Local -CliPath 'D:/微信web开发者工具/cli.bat'`，才启动电脑Java并连接127.0.0.1；此配置不用于手机扫码。
5. 开发脚本写入被Git忽略的 `config.local.js` 和 `project.private.config.json`。切换配置后重新编译并重新扫描二维码，旧会话会清除，需要重新登录。截图中调试器「已连接」只表示远程调试通道连接，并不说明业务后端连接成功。
6. Phone模式用于开发调试；当前IP后端测试需在微信打开调试模式，关闭调试的普通预览 / 体验版可能仍被合法域名限制。正式包使用 `-Target Production -ApiBase https://已登记的后端域名`，该模式拒绝IP / HTTP并启用平台域名校验，不修改或绕过服务器TLS。

`config.js` 的默认后端为空，避免新克隆误连正式用户数据。独立验收可传 `-Target Local -ApiBase http://127.0.0.1:4194 -NoBackend`，须自行启动隔离数据后端。绝不能把验收数据导入服务器。

## 登录与服务配置

已有账号可直接用账号密码登录。邀请码已退役，注册为普通用户，通过规范小测或管理员批准成为探索官。管理员实际改变普通用户 / 探索官身份后，恢复 5 次答题机会并使旧答卷失效；停用账号仍不能答题。

微信 code 换取身份仅由 Java 调用官方接口。未绑定时展示绑定已有网页账号 / 新建账号选择，不自动造号；已有账号需验证密码，新账号设置用户名、密码与昵称。不会根据昵称合并账户或生成虚构邮箱。解除绑定需要当前密码，并撤销该账号原生会话，网页会话独立。

仅需要本机微信登录时，在项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/configure-wechat.ps1 -AppId wxd52e9ecd6a2b1693
```

按本机隐藏提示输入 AppSecret，不发到聊天。脚本使用当前Windows账号DPAPI加密，存于仓库外 `../explore-shoot-部署配置/wechat.local.json`；配置不能跨Windows账号直接解密。服务只在启动时读取解密值，配置不存在时隐藏微信入口，账号密码登录不受影响。

服务器由管理员通过受保护环境配置 `WECHAT_APP_ID` / `WECHAT_APP_SECRET` 后重启服务，不能将本机DPAPI文件上传Linux。v6.8.0未配置真实微信登录；v6.8.2已按单次授权启用云端test模式并验收真实一键登录，原正式账号微信绑定不因此自动创建。

## 微信一键测试登录与正式数据隔离

在本机隐藏输入中配置测试模式：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/configure-wechat.ps1 -TestLogin
```

密钥通过Windows DPAPI加密，当前用户可解密，源码脚本带UTF-8 BOM以兼容Windows PowerShell中文目录。工具不依赖安全模块自动加载，AppSecret不出现在参数、源码或聊天。服务器需在固定版本部署之后，另经授权运行 `tools/deploy/configure-wechat-server.ps1`；密钥只经已核验SSH标准输入写入自己的服务器root专用600权限环境文件，不上传Windows加密文件。

模式由 `WECHAT_LOGIN_MODE` 控制：`test` 允许不预先注册 / 绑定的一键测试登录，创建普通测试账号；`bound` 支持正式微信登录与首次账号绑定 / 新建选择（保留旧测试数据但不允许其登录）；`off` 关闭微信入口；`production` 在保留正式绑定登录前强制检查无测试数据。测试账号使用独立wechatTestBindings和明确账号标记，不能转为正式账号，不能合并到已有账号；测试会话只在test模式的原生通道有效。

测试期间可使用私人打卡、照片和护照；不向社区提交公开作品、共创或举报，不计入全站点赞数。正式上线前停服、核对数据目录，运行：

```powershell
java -jar backend/target/explore-shoot-backend.jar --tool=retire-wechat-test --check
java -jar backend/target/explore-shoot-backend.jar --tool=retire-wechat-test --apply
```

工具先在当前data/maintenance-backups生成完整数据ZIP并逐文件验证，再清理测试账号、测试身份映射、会话、打卡、照片、头像、通知和测试评价；其余账号 / 正式绑定 / 真实记录不删除。照片被其他内容引用会拒绝，文件被占用时队列保留，解除占用后重复执行。保留必要维护备份与审计；备份受控保管，不能迁入正式活跃数据。生产模式发现任何测试账号 / 映射 / 待清理队列即拒绝启动，不会静默带入正式账号数据。

### 本轮追加：同账号登录、楼宇轮廓维护

- 未绑定微信登录后返回 5 分钟一次性票据，不返回 OpenID、session_key 或身份摘要。用户明确选择「绑定已有账号」（验证网页密码）或「创建新账号」（设置用户名、密码、昵称）；两端使用同一 users 主记录，不按昵称自动合并。绑定成功后重复票据失效，停用 / 删除 / 已绑定冲突在服务器拒绝。
- 历史 `test` 模式继续隔离；它不会静默转正。需要保留历史测试记录的试点可使用 `bound`，测试会话失效但记录不删除；正式 `production` 的既有测试数据检查保持不变。
- 顶级管理员在网页「护照与印章 → 楼宇 → 重画轮廓」或小程序「楼宇关联 → 重画轮廓」操作。支持放大、平移、顶点调整、重画、内院与撤销。服务器检查像素边界、自交、内院包含 / 重叠和 revision 冲突。普通管理员仍可维护楼名与点位关联，但不能改轮廓。
- 每次轮廓保存前，将修改前完整有效轮廓、修改后结果、操作者和时间保存至当前后端数据目录 `maintenance-backups/passport-atlas/*.json`，写后核对，Linux 权限 600；随后在数据库保存覆盖轮廓。失败不替换当前轮廓；普通关联编辑保留已有轮廓。该私有目录不提供下载接口，运维应与日常数据备份一起受控保管，不能放入静态资源。回退时按备份的 before 字段经同一顶管保存接口提交并使用当前 revision，不直接覆盖整个数据库。
- HTTPS 接的是 Java 后端接口，不是 web-view。当前公网域名 / 微信 request、downloadFile 合法域名仍需实际核验，编译及 localhost 验收不代表可提交平台公开发布。


### 本轮追加：网页视觉对齐与地图服务

- 「我的」按当前网页保留引导卡片、八项工具的顺序和尺寸、三项下划线内容分类；私人打卡从右上角账号菜单进入，公开作品仍由对应工具进入，管理入口保留在账号菜单。隐藏的工具不保留格子。图标直接由共享矢量生成，不重画另一套。
- 浅色 / 深色语义色向网页对齐；深色工具使用同一套蓝 / 绿 / 紫色层次。Dock 保留两组玻璃外观，切换不使用实时模糊或位置动画。WXML 自定义组件仅使用显式 class 选择器，避免标签选择器在组件 WXSS 中失效。
- 用户明确要求去掉地图来源覆盖字及展开来源入口。界面已删除这些字样；原数据、许可证与仓库来源清单保留，地图 / 三维功能不删。OSM 仍仅用于网页八处建筑轮廓，不参与步行算路，原生底图由微信提供。
- 顶管二次验证后的地图配置分「网页地图 SDK」和「小程序地图服务」。小程序底图仍为微信原生 map；腾讯 / 高德 / 百度选择控制步行路线数据，不冒充可直接替换原生底图。接口为 `POST /api/admin/map-config/mini`、`GET /api/maps/mini-config`、原生专用 `POST /api/maps/walking`；原生网关添加 `/api/mini` 前缀。三家 Web 服务 Key 只留在服务器，读取只返回是否已配，不回显密钥；留空保留。
- 原生服务切换独立 revision，冲突拒绝保存，不改变网页 SDK 配置。腾讯未单独配置时兼容既有腾讯 Key；另两家需要自己的 Web 服务 Key 和授权额度。路线请求不持有全局写锁，外部连接限时 / 限量，坐标统一在边界转换，过期账号和切换配置后的返回不重绘。
- 地图组件没有通用 `theme` 参数；未配置微信平台自定义样式时不能承诺底图跟随手动深色。当前深色保证应用界面，不通过图片反色伪造地图主题。
