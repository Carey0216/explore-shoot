## 启动与入口

双击 `启动项目.cmd` 启动用户端，双击 `打开管理端.cmd` 打开后台。双击 `停止项目.cmd` 停止两个端口的服务，数据保留。已安装 Node.js，无需 npm 安装。

- 用户端：[http://explore.localhost:4174](http://explore.localhost:4174)
- 管理端：[http://admin.localhost:4176](http://admin.localhost:4176)
- 用户独立登录页：用户域名下 `/login.html`；邀请码注册页：`/register.html`。管理独立登录页：管理域名下 `/login.html`，管理端不开放注册。
- 超级管理员账号：`admin`。沿用原版的管理密码；若原版未修改，为 `Explore2026!`。
- 浏览器若不解析 `.localhost`：用户端可用 `http://127.0.0.1:4174`，管理端可用 `http://localhost:4176`。不同域名的登录状态独立，切换访问地址时需要重新登录。

这两个地址为本地独立域名，未购买公网域名。服务只监听本机 `127.0.0.1`，用户端不显示管理端入口，用户服务也不提供管理接口或后台页面。两端使用不同 HttpOnly Cookie，后台逐项检查权限。

## 推荐体验顺序

1. 进入管理端 → 邀请码 → 生成邀请码。可选择自动生成，或手动填写 6—30 位数字 / 英文字母（支持纯数字与前导零）。可设置总邀请名额、有效天数与备注；复制后提供给体验者。「调整名额」可随时编辑总名额（1—500，不能低于已注册人数），并保留原有使用记录和停用状态。
2. 用户端 → 登录 / 注册 → 独立邀请码注册页面。填写账号、昵称、密码与有效邀请码，成功后回到此前浏览页面。后台的「用户账号」及「邀请码使用记录」都能查看注册归属。
3. 浏览发现页、筛选主题、收藏；顶部搜索仅在发现页显示，手机点击入口、桌面输入后回车，进入独立搜索页面，实时查看匹配点位，也可快捷搜索或清除关键词。点击卡片「去这里」或详情「到这里去」进入步行导航。主菜单也有独立「步行导航」，可选校园点位、地图选点或我的位置作为起点。无需登录即可规划路线。
4. 「出发探索」选择时间、人数、节奏与探索方式。「查看路线」可先看编号点位与腾讯在线步行路线；开始后用「定位并指路」查看下一站距离、方位和绿色路线，也可进入完整网页导航，或选择腾讯地图 App / 手机网页版。完成或跳过当前站后自动切换下一站。
5. 拍摄任务可以「打开摄像头」内建拍摄，或「选择照片」使用系统文件 / 相册选择器。选择器不设置强制调用相机的 `capture` 属性；具体相册菜单由手机系统提供。读取压缩、传输、服务器保存各阶段都有反馈，传输百分比来自实际上传字节；失败保留照片并支持重试。浏览器不能解码的 HEIC 等格式会提示改用 JPEG / PNG。
6. 有需要时手动开启实时轨迹。结束后在「探索手记」查看照片，填写感受、评分，导出带照片的独立 HTML 手记。
7. 「我的」申请校园探索官。后台通过申请后，用户可上传照片、地图选点并发布新点位，也可在点位详情提交问题反馈。
8. 新点位立即展示「由社区共创者上传，请自行分辨」。管理员编辑和核实资料后，选择认证，用户端显示「已经过认证」。点位反馈不会自动下架内容，由后台审核后选择处理、上下线或不采纳。
9. 超级管理员在「管理员账号」创建普通 / 超级管理员。普通管理员管理用户和全部内容，但不能查看或操作管理员账号管理。

管理端收到申请和反馈后约每 10 秒刷新；用户端每 12 秒同步内容版本与探索官身份，也可手动刷新。编辑表单与弹窗打开时不会自动覆盖输入。

用户在「我的 → 编辑个人资料」修改昵称和头像。管理员可通过顶部头像按钮或「设置 → 编辑昵称与头像」修改自己；普通 / 超级管理员均可使用。支持选择照片、拖动 / 缩放自选固定方形区域（最大 512 像素）、重新居中、实时预览、恢复默认头像、真实上传进度及失败重试。修改后登录账号、权限和邀请码归属不变；用户已有点位同步新的共创署名。

## 密码与数据

用户在「我的 → 修改密码」，管理员在「设置 → 修改自己的密码」中验证当前密码并修改。管理员也可重置用户密码；超级管理员可重置其他管理员密码。更改密码、停用或删除账号会撤销相关登录。

- `data/store-v2.json`：当前账号、邀请码、权限、共创内容、探索记录与地图配置。
- `data/media/`：本地照片。社区点位照片公开展示；手记照片只允许所属用户读取。照片压缩为 JPEG，并移除 EXIF / GPS 等元数据。
- `data/avatars/`：当前用户 / 管理员的头像，只允许所属账号登录后读取。头像不上传 GitHub，不提供公开地址，服务端清除 EXIF / GPS 元数据。完整备份应包含此目录。
- 密码存储为带随机盐的 scrypt 哈希，不能从哈希还原明文。不要通过直接修改哈希字段来改密码。
- `ADMIN_PASSWORD` 只用于全新数据目录的初始管理员创建，不能覆盖已经存在的账号密码。
- `data/store.json` 与 `backups/store-v1-*.json` 保留原型数据；`legacy/` 保留旧版代码与文档。旧虚构点位和匿名记录没有混入真实校园与新账号数据。
- 备份时停止服务后复制整个 `data` 文件夹。其中包含个人记录、密码哈希和地图安全密钥，应保存在你信任的位置。

## 地图与设备

> v4.2.2 已正式发布，GitHub Latest 为 `v4.2.2`。当前配置已完成 WebService 权限与额度联调，西校区内部及双向跨校区路线已由真实腾讯请求和网页绘制验证；实际手机 GPS、门禁与道路通行仍需实走验收。

当前 v4.2.2 继续将地图、步行规划、定位组件和外部地图入口统一到腾讯位置服务。校园地图、路线预览、步行导航、探索下一站和手记轨迹共用腾讯 GL；不再使用旧 OSM 道路图算路，腾讯失败时明确报错，不切回旧路网或补画穿楼直线。管理端「设置 → 腾讯地图」配置自己的 Key；Key 和业务数据均不上传 GitHub。

腾讯 Key 需启用 **WebService API**，并为步行规划、逆地址解析及坐标转换分配可用额度。GL 底图可用并不代表这些服务已启用；状态 199 表示未开启 WebService API，121 表示每日额度达到上限。详细设置、服务说明与排查见 [腾讯地图接入说明](腾讯地图接入说明.md)。西校区和跨校区不再受原本 33 段旧道路资料限制；真实请求已验证西校区内部及双向跨校区路线，网页已绘制经过过街天桥的腾讯路线。返回体育馆时距点位约 64 米，显示入口差距。实际手机定位、门禁及道路通行仍需实走核对。

当前版本保留精简控件：视角默认一个小按钮，点击展开，框外点击 / Escape 收回；缩放按钮、定位图标和全校范围共用 Liquid Glass 按压、光泽、波纹与回弹。支持滚轮、捏合、45° 旋转、归北和倾斜 / 俯视，保留版权及比例尺。

点位与历史轨迹继续以 WGS84 保存，腾讯显示 / 请求使用 GCJ-02，新版定位组件的结果换回 WGS84 后进入原有业务流程。未批量修改旧坐标；转换保留 MIT 授权并需实地校验。原 campus.geojson 与老算路工具只保留作历史资料，不在当前网页中加载或作为导航兜底；校园范围是项目的内容边界，并非腾讯实时围栏。

路线距离、预计时间、路线图和步骤来自腾讯 Walking 服务。相同路线在当前页面内存缓存五分钟，合并重复请求，队列间隔至少 450 毫秒；两次可靠定位确认偏航后重算，重算间隔至少 30 秒。异步算路显示进行状态，切换起终点、关闭目的地或退出后旧结果不会覆盖新路线。腾讯返回的路线终点距离所选点位超过 30 米时提示确认入口，不伪造连接道路。

定位使用腾讯新版 [H5 定位组件](https://lbs.qq.com/webApi/component/componentGuide/componentGeolocation)，严格高精度模式，不接受城市级 IP 位置作为导航。普通浏览器的传感器权限仍由浏览器 / 手机系统提供；腾讯组件统一处理定位途径、坐标与位置服务。精度超过 80 米不提供可靠指路；轨迹记录过滤校园外和超过 200 米的定位点。只在点击后申请位置，不因打开网页自动定位。

启用定位时腾讯处理位置信息，在线算路发送起终点坐标，地图绘制也由腾讯处理点位和轨迹坐标；项目不保存单纯导航定位。只有单独开启「实时轨迹」后，轨迹保存至项目服务器并仅当前账号可见。拒绝权限、切到后台、离开、结束或到达时停止持续定位。摄像头与定位须在 localhost 或 HTTPS 上授权。网页导航提供前台跟随、步骤和可选中文语音，不能在锁屏 / 后台提供腾讯 App 同等导航能力。

外部入口改为腾讯地图 App 和手机网页版，使用 GCJ-02 起终点；电脑在本项目规划步行，也可打开腾讯地图查看目的地。腾讯 URI 的网页版步行仅适用移动端，不能把电脑 URI 当作可用步行导航。手机 App 唤起受设备、浏览器及安装情况限制。参考 [腾讯 GL 服务类](https://lbs.qq.com/webApi/javascriptGL/glDoc/glDocService)、[App 路线 URI](https://lbs.qq.com/webApi/uriV1/uriGuide/uriMobileRoute)、[Web 路线 URI](https://lbs.qq.com/webApi/uriV1/uriGuide/uriWebRoute)。

## 配图与内容边界

3 张校园参考配图来自[国家民委发布的北方民族大学介绍](https://www.neac.gov.cn/seac/mwjs/201504/1009156.shtml)，原文注明来源北方民族大学。页面显式标注参考配图，并在详情说明不代表点位当前现场；未将配图伪称为对应教学楼或运动场的实拍。图片用于本地预览，正式公开上线前应替换为自己拍摄或已获得授权的照片。

交互与照片发现的视觉方向参考[可颂 App](https://apps.apple.com/cn/app/%E5%8F%AF%E9%A2%82-%E5%8F%91%E7%8E%B0%E7%94%9F%E6%B4%BB%E7%9A%84100%E7%A7%8D%E5%8F%AF%E8%83%BD/id6479338276)，未复制其品牌和界面资源。已加入按钮反馈、卡片悬停、收藏变化、任务进度、弹窗过渡和减少动态效果支持。

v2.1 整理双端为校园摄影、暖白和森林绿视觉，采用浮动导航与轻量卡片；玻璃质感通过 CSS 背景模糊、饱和度、边缘高光和交互过渡实现。手机与桌面布局分别适配，不支持模糊的浏览器有不透明样式，系统减少动态效果设置会关闭非必要动画。

v2.2 将玻璃交互统一到桌面 / 手机和用户 / 管理两端，含登录页与动态表单：高光跟随指针 / 触点、按下时亮光与形变、松开后的回弹、栏目选中层的滑动变形。支持键盘操作与减少动态效果；照片卡片保留内容展示，同时提供按压反馈。这是参考 Apple 交互方向的 Web 实现，不是原生系统组件。

路线时间包含步行、每点位 2 分钟拍摄和预算的 20% 余量。未实走路线注明估算；后台可登记实走时间、调整计划，至少 3 次记录后注明校准。偏好匹配采用审核任务模板，暂未调用 AI 模型，界面说明此限制。

## v3.0 地图和导航（历史实现）

以下记录 v3.0 当时的实现，用于考古；当前地图与导航以本页「地图与设备」及当前版本说明为准。

用户端采用暖灰背景、蓝色主按钮、浅蓝次级玻璃和蓝色选中层，桌面与手机的光环、按压、回弹继续共用交互层。

独立导航页支持校内步行路线、起终点标记、估算距离 / 时间、转向步骤、定位跟随、可选中文语音、剩余距离和行进进度。两次可靠定位确认偏离参考路线后重新规划；定位精度超过 80 米时暂停指令，接近目的地（30 米内且精度不超过 25 米）后结束定位。导航不会替用户完成探索任务。页面滚动不触发地图滚轮缩放。

实时导航须在本机 localhost 或 HTTPS 手机测试地址打开并允许定位；桌面定位常不够精确，可先用手动起点体验路线。位置仅留在页面内，离开页面、切到后台、拒绝权限、终点关闭或到达时停止，不提供锁屏 / 后台持续导航。语音能否播报取决于浏览器和系统中文语音包。

手机系统浏览器的「用手机地图 App / 网页版打开」提供高德官方 iOS / Android 步行 URI，携带 GPS 坐标并使用 `dev=1` 转换；未安装高德或在微信等内置浏览器中受限时，可选择网页版或回到网页内导航。电脑显示网页版入口，不承诺唤起手机 App。[高德官方 Android 路径规划文档](https://developer.amap.com/api/amap-mobile/guide/android/route)、[iOS 路线规划文档](https://developer.amap.com/api/amap-mobile/guide/ios/route)。外部地图仅在点击时接收起终点；项目不向外部服务上传导航定位。

地图默认为在线 OpenStreetMap 街道底图，可通过右上角图层按钮切换校园详图；底图连接失败时使用本地地理资料。在线底图不再叠加旧建筑示意层。校园详图和路线取自 OSM 官方校区范围数据，v3.0 于 2026-10-05 重新获取，包含 33 段公开道路；其中最近的道路编辑是 2024-05-18，部分校内道路仍在 2019—2021 年，不能代表新近实地测绘。没有虚构道路、入口或实时封路数据；虚线靠近段需确认实际通行入口。暂不提供校外、驾车路线。既有管理端高德 Web JS Key 配置入口仍保留。

维护时运行 `npm run map:refresh` 重新读取公开校区资料，失败保留原文件，不发送个人位置。更新道路文件后刷新浏览器即可。地图要素保留来源、获取日期、对象编辑日期及 ODbL 署名，在线瓦片按普通浏览请求，不批量预取或下载离线瓦片。

`tests/journey.cjs` 检查转向、路线进度、虚线靠近段、手动 / GPS 起点、连续偏离重规划、定位精度、到达、切后台、过期回调和终点关闭；测试位置不写入真实数据。

版本发布：先运行 `npm test`，提交中文更新日志和源码，推送 main 与版本标签，再运行 `npm run release` 在既有 private 仓库创建中文 GitHub Release；凭据由现有 Git 登录提供，不保存到项目。
